TP1: Punteros y Gestión de Memoria en C Completo

Fundamentos de punteros y gestión de memoria dinámica en C. El objetivo es comprender la asignación de memoria dinámica y el direccionamiento por punteros para implementar programas utilizando estructuras de datos de gran tamaño.

1. Punteros Básicos

Declaración de punteros, operador de dirección & y operador de indirección *.

  • archivo.c - Imprime dirección de x, dirección en p, y valor *p
  • ej1-2.c - Demuestra reasignación de punteros: después de x = y, ambos apuntan a b, por lo que *x = 5 modifica b (no a). Resultado final: a=10, b=5

2. Punteros y Arreglos

El nombre del arreglo evalúa a su dirección base. Almacenamiento en orden de fila (row-major).

  • ej2-1.c - Accede al 5to elemento de float a[5] usando notación de puntero *(a+4)
  • ej2-2.c - Imprime direcciones de todos los elementos de una matriz 3x4 para demostrar almacenamiento row-major (direcciones incrementan de 4 en 4 bytes)

3. Punteros a Punteros

  • ej3-1.c - Doble indirección: num empieza en 123, *p1 = num-23 lo hace 100, **p2 = *p1 * 2 lo hace 200

4. Organización de Memoria

Teoría sobre los cinco segmentos de memoria:

Stack

Variables locales, parámetros de funciones, retorno

Heap

Memoria dinámica (malloc/free)

BSS

Variables globales no inicializadas

Data

Variables globales inicializadas

Text

Código ejecutable (solo lectura)

5. Asignación Dinámica de Memoria

  • ej5-1.c - Uso básico de malloc(sizeof(int)), almacena valor 50
  • ej5-2.c - Error de compilación: redeclaración de variable
  • ej5-3.c - Matriz 3x4 con filas unificadas (bloque contiguo único). Asigna un bloque para todos los elementos y un arreglo de punteros a filas

TP2: Uso de un Cluster Completo

Uso práctico del cluster III-LIDI (IP: 163.10.34.49) utilizando el gestor de carga de trabajo SLURM. Se enfoca en transferencia de archivos SSH/SCP, envío de trabajos, gestión de nodos e inspección de recursos.

1. Acceso al Cluster

Login SSH con credenciales institucionales.

2. Gestión de Archivos

Creación de directorios, subida de archivos con SCP (serie.c).

3. Inspección de Recursos (sinfo)

Partición Nodos Estado
Blade (default) 16 Disponible
XeonPHI 1 Down
GPUS 2 Down

Especificaciones de Nodos Blade

  • Procesador: Intel Xeon E5405 @ 2.00GHz
  • Sockets: 2
  • Cores por socket: 4
  • CPUs totales: 8
  • Threads por core: 1
  • RAM: ~7.79 GB
  • Arquitectura: NUMA

4. Envío de Trabajos (sbatch)

Compila y ejecuta serie.c (imprime hostname y número de core vía sched_getcpu()).

Directivas SLURM: -N, --exclusive, --partition, -o, -e

Nota importante: Las opciones por línea de comandos anulan las directivas del script (verificado experimentalmente: sbatch --nodelist=nodo10 prevalece sobre #SBATCH --nodelist=nodo16).

5. Estados de Trabajos y Cancelación

Estado Significado
R RUNNING (en ejecución)
PD PENDING (con razón Resources)
CG Completing (finalizando brevemente)
COMPLETED Completado exitosamente
TIMEOUT Excedió límite de tiempo (SIGTERM, exit code 0:15)

TP3: Optimización de Alto Rendimiento Completo

Técnicas de optimización de código de alto rendimiento. Este es el TP más extenso, organizado en 9 partes (1P/ hasta 9P/). Cada ejercicio explora una técnica de optimización manual, midiendo su impacto en tiempo de ejecución y uso de memoria. Compilación sin auto-optimizaciones del compilador (-O0) para aislar efectos manuales.

Resultados Medidos

Ejercicio Técnica Original Optimizado Mejora
2.2 float → int 5.524s 3.476s ~37% más rápido
3 int → char (bool) 2.648s, 1526 MiB 2.144s, 381 MiB 75% menos memoria
4 Código inline 1.765s 0.255s ~85% más rápido
5 Loop unroll + ILP 0.148s 0.035s ~76% más rápido
6 Subexpresión común 1.499s 1.049s ~30% más rápido
7 Evitar ramas 7.291s 6.385s ~12% más rápido
8 Localidad de caché 45.895s 3.251s ~93% más rápido (14x)
9 SIMD (SSE 4.2) 0.790s 0.303s ~62% más rápido (2.6x)
Ejercicio 8 - Mayor mejora: Cambiar acceso column-major a row-major en una matriz 50000x10000 redujo los fallos de caché L3 en un 93.75% (de 5×10⁸ a 3.125×10⁷).

TP4: Evaluación de Rendimiento En Progreso

Evaluación de rendimiento de aplicaciones paralelas usando OpenMP. Se enfoca en instrumentación para medición de tiempo, escalabilidad fuerte y escalabilidad débil.

1. Programa Julia Set con OpenMP

El programa principal (julia.c) computa fractales del conjunto de Julia. Compilación: gcc -fopenmp -O3 julia.c -o julia. Dos parámetros controlan las dimensiones de la imagen (alto × ancho).

2. Ejercicio 1.i - Escalabilidad Fuerte

  • Tamaño de problema fijo (alto 240,000, ancho 2,000)
  • Varía cantidad de cores: 2, 4, 6, 8, 10, ..., hasta total de cores
  • Requerido: script, gráfico de tiempo de ejecución, gráfico de speedup (con lineal ideal), gráfico de eficiencia paralela, y análisis

3. Ejercicio 1.ii - Escalabilidad Débil

  • El tamaño del problema crece con los cores (alto 8,000 × ancho 2,000 por core)
  • Requerido: script con dimensionamiento dinámico, gráfico de tiempo de ejecución, análisis

4. Ejercicio 2 - Instrumentación de Programa Serial

Completar programa2.c con mediciones de tiempo para ejecuciones cortas pero representativas, y extrapolar para n=1,000,000.

5. Ejercicio 3 - Cálculo de Speedup

Calcular speedup de programas optimizados del TP3 ejercicios 8 y 10 vs. versiones no optimizadas.
